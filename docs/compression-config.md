# T14 compression and feature-configuration rules

Date: 2026-09-06. This document records the source identity, ownership and
final `.config` semantics for the compression and related feature toggles. It
does not claim a full kernel link, runtime crypto API test or device result.

The base kernel is `Ace6-Development/android_kernel_oneplus_sm8750@cb967c26c2c5689108fa28d3c3be2aba6ba71f5f`.
The source clones used for this audit were clean at those commits. Local
patch and extra-file hashes are recorded in `docs/evidence/t14-compression.json`
and the legacy inventory; the local hashes remain the authoritative bytes for
the build.

`02_lz4.patch` and `03_zstd.patch` are gated by `lz4_zstd`. When that input is
false, neither replacement patch nor its replacement source copies are used.
Native `CONFIG_CRYPTO_LZ4`/`CONFIG_CRYPTO_ZSTD` are not blanket-disabled,
because F2FS, initramfs and other selected kernel features can depend on the
in-tree compression backends. This is an explicit source-replacement
semantic, not a silent feature leak.

## Final configuration table

`CONFIG_ZRAM_DEF_COMP` is generated by Kconfig from the selected choice; the
string is not hand-edited after `olddefconfig`.

| Input | `false` result | `true` result | Dependency/interaction |
|---|---|---|---|
| `lz4_zstd` | Do not apply 02/03 or copy replacement sources; retain only dependency-backed native compression settings. | Apply 02/03, copy the pinned LZ4/zstd adaptations, and explicitly enable `CONFIG_CRYPTO_LZ4` and `CONFIG_CRYPTO_ZSTD`. | This toggle controls replacement source ownership, not every kernel use of LZ4/zstd. |
| `lz4kd` | `CONFIG_CRYPTO_LZ4K=n`, `CONFIG_CRYPTO_LZ4KD=n`, all LZ4K/LZ4KD library backends `n`; select `CONFIG_ZRAM_DEF_COMP_LZORLE=y`, yielding `CONFIG_ZRAM_DEF_COMP="lzo-rle"`. | Enable the LZ4K/LZ4KD crypto and library backends; select `CONFIG_ZRAM_DEF_COMP_LZ4KD=y`, yielding `CONFIG_ZRAM_DEF_COMP="lz4kd"`. | The fallback uses the base kernel's LZO backend and remains valid without patch 04. |
| `show_all_algos` | Explicitly disable `CONFIG_CRYPTO_LZ4HC` and `CONFIG_CRYPTO_842`. | Explicitly enable LZO, LZ4, zstd, deflate, LZ4HC and 842 crypto backends; LZ4K/LZ4KD are included only when `lz4kd` is also true. | The default compressor remains an independent choice. |
| `zram_writeback` | Explicitly disable `CONFIG_ZRAM_WRITEBACK`, `CONFIG_ZRAM_MEMORY_TRACKING` and `CONFIG_ZRAM_TRACK_ENTRY_ACTIME`. | Explicitly enable `CONFIG_ZRAM_WRITEBACK`; tracking remains independently at its base-config value. | Writeback still needs runtime `backing_dev` setup; the kernel option alone does not provide a device backing. |
| `better_net` | Explicitly disable `CONFIG_IP_SET`, `CONFIG_BPF_STREAM_PARSER` and `CONFIG_IP6_NF_NAT`. | Explicitly enable those three settings, then let Kconfig resolve their ordinary dependencies. | The exact 6.6 base retained the requested `n`/`y` values in both table runs. |
| `bbr` | Explicitly disable `CONFIG_TCP_CONG_BBR` and `CONFIG_DEFAULT_BBR`. | Explicitly enable `CONFIG_TCP_CONG_ADVANCED` and `CONFIG_TCP_CONG_BBR`; `CONFIG_DEFAULT_BBR` stays off, so enabling BBR does not silently change the default congestion control. | `CONFIG_TCP_CONG_ADVANCED` may remain enabled for other congestion algorithms while BBR itself is off. |

The resulting representative defaults were:

| Tree/config case | Default compressor | BBR | Better network | Writeback | Optional LZ4HC/842 |
|---|---|---|---|---|---|
| base, all requested features off | `lzo-rle` | off | off | off | off |
| base, all optional algorithm/network/writeback inputs on | `lzo-rle` | on | on | on | on |
| patch 04, all requested features off | `lzo-rle` | off | off | off | off |
| patch 04, LZ4KD only | `lz4kd` | off | off | off | off |
| patch 04, all requested features on | `lz4kd` | on | on | on | on |

## Static registration and build boundary

With the patch-04/all-algorithms configuration, `drivers/block/zram/zcomp.c`
contains the nine registered backend names: `lzo`, `lzo-rle`, `lz4`, `lz4hc`,
`lz4k`, `lz4kd`, `deflate`, `842` and `zstd`. The corresponding crypto,
library, zram registration, compression and decompression objects compile
with `ARCH=arm64 LLVM=1 LLVM_IAS=1`.

This verifies source registration and representative compile paths. It does
not verify a linked Image, `/sys/block/zram*/comp_algorithm`, actual crypto
API round trips in a booted kernel, writeback backing-device behavior, BBR
runtime selection or real-device behavior. Those remain later build/runtime
gates.
